# 需求基线（定稿版）

> 状态：P1 定稿 · 本文是需求的唯一真源。变更只改这里，再同步 `06`（契约）与 `05`（计划）。

## 1. 核心定位

| 层 | 由谁承担 | 职责 | 成本 |
| --- | --- | --- | --- |
| 总指挥 | DSH + FreeLLMAPI 免费聚合网关 | 任务拆解、流转判断、结果汇总 | 不消耗三家额度、不充值 |
| 干活 | Trae / Qoder / WorkBuddy 官方 CLI（原生 MCP） | 真实推理与产物 | 三家的赠送免费额度 |
| 调度 | **本项目**：聚合调度 MCP | 账号池、轮换、子进程、任务协议、上游同步 | 本机 CPU |

## 2. 一句话调度逻辑

> Trae 组、Qoder 组、WorkBuddy 组互相可以并行；**同一个分组内串行，同一时间只激活一个 CLI 进程，
> 其余备用进程保持休眠不登录、不发请求，轮到它的时候再拉起 / 激活。**

这条是一切的基准：所有设计取舍都为它服务，任何改动若破坏它即为缺陷。

## 3. 环境分离

| 角色 | 装什么 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 开发机 | Python 3.12；**不装** DSH / Trae / Qoder / WorkBuddy | 编码、Mock 调试、Schema 定义、版本管理、拉取上游更新 | 依赖真实 CLI 才能跑的业务验证 |
| 工作机 | 三家 CLI + 多账号凭据 + DSH + FreeLLMAPI | 部署、真机联调、账号实测 | 当作开发环境改设计 |

工程推论：
- 开发机全部测试必须是 Mock 或 Fake 执行器，**不需要任何环境变量与 CLI**。
- real 相关代码允许在开发机写完，只做静态检查与单测。
- Mock 与 real 走**同一条调度代码路径**，只替换 Runner 实现。

## 4. 账号池策略（核心）

- 分组类型：
  - `kind: cli`（内置三组）：`trae_group` / `qoder_group` / `workbuddy_group`，吃免费额度；
  - `kind: api`（自定义名）：任意 OpenAI 兼容供应商，DSH 自己充值也能用（见 §4.1）。
- 分组内策略对两类组**完全一致**（单实例、串行、故障切换、冷却）。
- 组内：**单实例激活**，同一分组同时只跑一个任务、只在线一个账号。
- 切换触发：额度耗尽、配额报错、账号封禁、鉴权失效、连续超时失败、手动下线。
- 未激活账号：进程休眠 / 不拉起，不维持会话、不主动请求。
- 跨组：并行，互不阻塞。
- 切换上限：单任务最多尝试 `max_account_attempts` 个账号（默认 3），超限则任务失败。

## 5. 协议与交付规范（inbox 任务队列）

每个任务一个独立工作目录：

```
workspace/<task_id>/
  manifest.json   任务清单（目标、验收标准、版本号）——提交时写入，不可变
  prompt.md       渲染后的完整指令（含验收标准与运行约定）
  inbox/request.json  给 CLI 的请求（协议核心）
  artifacts/      CLI 产物
  stdout.log / stderr.log   输出（**脱敏后**）
  result.json     调度器写回的结构化结果
  .DONE           完成标记
  .FAILED         失败标记
```

- 完成以 `.DONE` 出现为准，**不以进程退出码为准**（CLI 可能常驻或先退出）。
- `.DONE` 与 `.FAILED` 互斥，后写的会清掉前一个。

## 6. 上游自动更新（可选能力）

- 拉取上游仓库，同步 CLI 命令/参数、MCP 入参出参 schema、模型清单。
- **必须先备份**，更新后做兼容性校验，任何失败自动回滚。
- 支持手动触发（`update_upstream` / `upstream-update.bat`）与仅检查版本。

## 7. 传输与模式

| 维度 | 选项 |
| --- | --- |
| 传输 | SSE（主推，局域网/本地，方便换 DSH / Cherry / LangGraph）；stdio（工作台原生本地 MCP） |
| 模式 | `mock`（开发机，不拉起 CLI，可模拟账号轮换与报错）；`real`（工作机，管理真实子进程） |

两种传输共用同一套工具实现；两种模式共用同一套调度逻辑。

## 8. 明确不做

1. 同组并行（会大幅抬高风控识别概率）。
2. GUI 自动化 / 窗口捕获 / 视觉识图（本项目走 CLI，不做 GUI）。
3. 抓包、逆向 Electron 接口、注入渲染进程。
4. 账号密码托管：凭据只从环境变量读，配置文件只存变量名（API key 同样只写 `env:变量名`）。
5. 自动注册、自动登录、验证码处理、绕过限流。
6. DSH 的提示词 / DAG / 审批节点配置内容（本包只给接入指引）。
7. 产物归档到 md 的具体实现（由编排侧决定，本包只提供产物路径与校验和）。

## 9. 约束与风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 三家 CLI 参数不统一 | 调用方式分叉 | `CliProfile` 收敛差异，命令可由 `accounts.yml` 覆盖 |
| 上游改 CLI 参数 | MCP 调用报错 | 备份 + 校验 + 回滚；`update_upstream --check` 先探 |
| 免费额度限流 | 长等待/失败 | 组内冷却 `group_cooldown_s`、切换冷静期 `switch_cooldown_s` |
| 多账号额度互通性未知 | 切换可能无效 | 工作机实测后记录到 `09` |
| 进程属当前登录会话 | 注销即全终止 | 文档明确：锁屏可跑，注销不跑 |
| 凭据泄露 | 安全事故 | 配置只存 `env:变量名`；日志/输出统一 `redact()` |

## 10. 验收口径（项目级 DoD）

1. 开发机：`pytest` 全绿（Mock/Fake），**无需任何 CLI 与环境变量**。
2. 工作机：只靠"拷目录 + 改 accounts.yml + 配环境变量 + 改 mode:real"即可跑通。
3. 额度耗尽场景：A 耗尽 → 自动标 FAILED → 切 B → 任务成功，且出参 `account_attempts=2`。
4. 同组串行 / 跨组并行可被观测证明（时间戳与日志）。
5. 上游更新失败时，`vendor/` 与版本文件都能回到更新前状态。
6. DSH 侧只传分组名与清单，无需感知账号切换。
