# 决策记录（ADR）

> 状态：持续更新。每条只记"为什么"，实现变动不作为历史。

## ADR-001 从 GUI 自动化转向 CLI 后台进程
- 阶段：P0（需求切换）
- 决策：放弃 UIA/DXGI 窗口操控，改为管理三家官方 CLI 的子进程 + MCP 通信。
- 理由：① 无前台窗口依赖，锁屏可跑；② 进程即账号，天然隔离会话与凭据；③ MCP 是结构化协议，
  比控件定位稳定得多，不会因客户端版本更新而失效；④ 风控面更小（同组只 1 个进程在线）。
- 代价：依赖三家 CLI 存在且参数稳定；无法操作只有 GUI 的功能。
- 状态：已定（这是本项目的立身之本）

## ADR-002 Runner 抽象：Mock 与 Real 只换执行器
- 阶段：P1
- 决策：`Runner` 接口 + `MockRunner` / `CliRunner` 两个实现，调度逻辑只有一份。
- 理由：需求硬性要求"开发机不需要安装三家 CLI 就能调试"。若 Mock 走另一条代码路径，
  那测的就不是真逻辑，Mock 形同虚设。
- 代价：Mock 必须模拟得足够像（含故障分布），否则测试通过不代表真机通过。
- 状态：已定

## ADR-003 文件协议（inbox/manifest/.DONE）而非 IPC
- 阶段：P1
- 决策：任务交付与完成判定全部走文件，不用 socket / 共享内存。
- 理由：① 产物天然落盘，DSH 可直接读；② 异常时现场完整（manifest+日志+标记）可复现；
  ③ CLI 只需支持"读文件、写文件、写标记"三种能力，适配成本最低。
- 代价：轮询有延迟（默认 0.2s），文件系统需可写。
- 状态：已定

## ADR-004 完成信号以 `.DONE` 为准，不以退出码为准
- 阶段：P1
- 决策：轮询 `.DONE`/`.FAILED`；进程退出只作为兜底判定。
- 理由：三家 CLI 可能是常驻 MCP server（不会自己退出），也可能一次性执行后立即退出。
  依赖退出码会在常驻场景下永远等不到结果。
- 代价：CLI 必须遵守写标记的约定（已在 prompt 与 request.json 中强制说明）。
- 状态：已定

## ADR-005 任务失败 / 排队 / 运行中都是 `ok=true`
- 阶段：P1
- 决策：`get_task_result` 的 `queued`/`running`/`succeeded`/`failed` 全部 `ok=true`，
  用 `succeeded` 布尔区分业务成败；只有工具本身出错才 `ok=false`。
- 理由：DSH 若把 `failed` 当协议错误重试，会重复消耗免费额度。协议层错误与业务层失败必须分开。
- 代价：编排侧必须同时看 `ok` 与 `data.succeeded`。
- 状态：已定

## ADR-006 切换账号上限 `max_account_attempts`
- 阶段：P1
- 决策：单任务最多尝试 N 个账号（默认 3），超限即任务失败。
- 理由：无上限会导致"全部账号都耗尽时无限循环切换"，既烧时间也可能触发风控。
- 代价：极端情况下（第 4 个账号才有额度）任务会失败，需人工调大。
- 状态：已定

## ADR-007 `next_available` 不回绕到自身
- 阶段：P1（测试发现）
- 决策：切下一个账号时，候选集合排除当前账号。
- 理由：单账号分组下会"切到自己"并静默成功，用户以为切了其实没切。
  测试 `test_switch_account_no_alternative` 覆盖此点。
- 代价：单账号分组调用 `switch_account` 返回 `POOL_EXHAUSTED`（这是正确行为）。
- 状态：已定

## ADR-008 凭据只从环境变量读，配置只存变量名
- 阶段：P1
- 决策：`accounts.yml` 的 `env` 值为 `env:VAR_NAME`，校验器拒绝明文凭据；启动时注入子进程环境。
- 理由：配置文件常随项目拷贝/提交，明文凭据必然泄露；环境变量不进版本库。
- 代价：工作机需额外配置环境变量（已写进部署文档）。
- 状态：已定

## ADR-009 输出与日志统一 `redact()`
- 阶段：P1
- 决策：`stdout.log`/`stderr.log`/`fail_reason`/日志中的 CLI 输出全部先脱敏。
- 理由：CLI 报错常回显 token 片段或请求头；一旦落盘就是长期泄露。
- 代价：误打码部分调试信息（可接受）。
- 状态：已定

## ADR-010 环境类错误不切账号
- 阶段：P1
- 决策：`is_env_error()` 命中（命令不存在、参数错误）时直接报 `CLI_NOT_FOUND`，不标记账号故障。
- 理由：这类错误换 100 个账号也解决不了，把账号标 FAILED 只会把好账号一起废掉。
- 代价：需要维护环境错误的识别关键词。
- 状态：已定

## ADR-011 上游更新必须"先备份、后校验、失败回滚"
- 阶段：P1
- 决策：任何更新前先整目录备份；更新后校验关键文件与 schema 可解析；失败自动回滚并保留备份。
- 理由：上游改参数会让 MCP 调用直接报错，没有回滚就只能手工恢复。
- 代价：磁盘占用（默认保留 5 份）。
- 状态：已定

## ADR-012 Mock 不校验凭据
- 阶段：P1（实测发现）
- 决策：`MockRunner.requires_credentials = False`，Mock 下缺环境变量不报错。
- 理由：开发机本来就没有凭据；若 Mock 也校验，`accounts.yml` 模板会直接让开发机跑不起来。
  "开发机无需凭据即可闭环"是需求，不是便利。
- 代价：Mock 测不到"缺凭据"路径 —— 用带 `requires_credentials=True` 的测试替身覆盖。
- 状态：已定

## ADR-013 环境级错误单独用 `error_code` 表达，且不标账号 FAILED
- 阶段：P1（开发机实测发现）
- 决策：CLI 不存在 / 依赖缺失 / 配置非法这类"任务根本没跑起来"的错误，
  写进 `get_task_result.data.error_code`，并且**不**把账号标成 FAILED。
- 理由：① 开发机没装 CLI 时，三账号会被依次标 FAILED，装上 CLI 后还要手工恢复；
  ② 编排侧需要分清"模型没干活"和"环境坏了"，前者可重试，后者重试无意义。
- 代价：多一个字段要解释；已写入契约 v1.0.1（只增不改）。
- 状态：已定

## ADR-014 API 只用 OpenAI 兼容协议，不做多协议适配
- 阶段：P2（需求新增）
- 决策：只实现 `POST {base_url}/chat/completions`（OpenAI 兼容），不做 Anthropic 原生协议。
- 理由：① OpenAI 兼容是事实标准，覆盖 DeepSeek / Kimi / GLM / Qwen / OpenRouter / one-api /
  vLLM / Ollama 等绝大多数供应商；② 一个适配器 + 可配 `base_url` 就能接任意家，维护成本最低；
  ③ 需要 Claude 时走中转站的 OpenAI 兼容端点即可。
- 代价：Anthropic 特有的 `system` 数组、`tool_use` 等无法直接使用（本期不需要）。
- 状态：已定

## ADR-015 分组放开为任意字符串 + kind 字段
- 阶段：P2
- 决策：`GroupName` 从 Literal 三选一改为 `str` + 正则校验；分组配置新增 `kind: cli|api`。
- 理由：要"挂任意家 API"就必须能自定义分组名；用 `kind` 区分行为比"按名字猜"更明确。
- 代价：未知分组名从入参校验阶段（`INVALID_ARGUMENT`）推迟到调度层（`GROUP_NOT_FOUND`）。
  用正则保证"明显打错的名字/非法字符"仍在入参阶段被拦。
- 状态：已定（契约 v1.1.0，向后兼容）

## ADR-016 API 组必须有日预算护栏（默认不限额但显式配置）
- 阶段：P2
- 决策：`api.daily_budget > 0` 时超限直接拒单（`POOL_EXHAUSTED`），账本落盘按天重置。
- 理由：API 花真钱，没有护栏等于把信用卡交给一个会重试的循环。默认 0（不限额）
  是给"本来就免费"的网关用；付费供应商必须显式填预算。
- 代价：需要维护 `.api_budget.json`；价格需人工填（未填时只统计 token 不算钱）。
- 状态：已定

## ADR-017 上下文超长/模型不存在不换 key
- 阶段：P2
- 决策：`context_too_long` / `model_unavailable` 标记为不可切换故障。
- 理由：这两类是 prompt/配置问题。若当成"key 坏了"去轮换，会把整组好 key 一个个标成 FAILED，
  额度没用完却全废了。
- 代价：需要区分"上游 5xx"（该换）与"我们请求错了"（不该换），靠状态码 + 错误体关键词。
- 状态：已定
